# 예정 작업

진행 순서와 상태는 `.agent/plan.md` 기준. 여기에는 각 작업의 범위·완료 조건·검증 방법만 둔다.

## 구조·성능 개선

2026-11-17 코드 점검 결과. 기능 추가 전에 진행한다.

### 상태 구독 선택자 전환

- 문제: `App.tsx`가 `useWorkspace()`·`useSettings()`를 선택자 없이 구독하고 편집마다 `documents` 배열이 새로 생겨 키 입력·커서 이동마다 앱 전체가 다시 렌더링된다. `WorkspaceTree`도 `tree`·`documents` 전체를 구독하고 행마다 `documents.some`을 돈다.
- 범위: 필드별 선택자와 `useShallow`, 커서 위치 표시를 자체 구독 컴포넌트로 분리, 트리는 변경 문서 ID 집합 선택자 사용, 편집기 값 비교를 모델 버전 ID 기반으로 변경
- 완료 조건: 키 입력·커서 이동 시 App·사이드바·트리가 다시 렌더링되지 않는다. 기존 동작 유지
- 검증: 렌더 횟수 테스트, `npm run check`, 큰 문서(1MB 이상) 입력 체감 확인

### App.tsx 분리

- 문제: `App.tsx` 2,200줄 한 컴포넌트에 상태·명령·메뉴·단축키·화면이 모두 있다.
- 범위: 메뉴 구성 → `workspace/menus.ts`, 팔레트 명령 → `workspace/paletteCommands.ts`, 전역 단축키·문서 생명주기·탐색 이동 → 훅, 사이드바·탭 바·문서 도구막대·상태 표시줄·개요 → 컴포넌트. 컴포넌트별 `*.module.css`로 `App.module.css` 분리
- 완료 조건: 동작 변경 없이 `App.tsx`가 화면 배치 중심으로 줄어든다. 분리한 모듈은 각각 테스트 가능
- 검증: 기존 테스트 통과, 분리한 메뉴·명령 모듈 단위 테스트 추가, 데스크톱 앱 화면·단축키 확인

### store.ts slice 분리

- 문제: `createWorkspaceStore` 한 클로저(1,000줄)에 복구·외부 변경·클립보드·프로젝트/세션·문서·파일 작업·영속화가 섞여 있다.
- 범위: 기능별 Zustand slice로 분리, 영속화 구독은 별도 모듈
- 완료 조건: 공개 상태·액션 이름 유지, slice별 테스트 가능
- 검증: 기존 store·App 테스트 통과

### 미리보기 렌더 비용 절감

- 문제: 변경마다 문서 전체를 ReactMarkdown으로 다시 파싱하고 제목 매칭이 O(n²), 컨텍스트 값·플러그인 배열이 매 렌더 새로 생긴다. Mermaid는 결과 캐시 없이 매번 초기화한다.
- 범위: 미리보기 갱신 디바운스, 블록 단위 메모이즈, 제목 조회 맵, Mermaid 결과 캐시(소스·테마·크기 키)
- 완료 조건: 큰 문서 편집 중 미리보기 갱신이 입력을 막지 않고 스크롤 동기화 유지
- 검증: 기존 미리보기·스크롤 테스트, 큰 문서·Mermaid 다수 문서 체감 확인

### 파일 변경 감시 전환

- 문제: `monitor.ts`가 3초마다 열린 폴더를 순서대로 다시 읽고 `JSON.stringify`로 비교한다.
- 범위: Rust `notify` 기반 감시로 변경 이벤트 전달, 폴링은 감시 실패 시 대체 수단으로만 유지
- 완료 조건: 외부 변경 감지·미편집 자동 갱신·미저장 충돌 안내 동작 유지, 유휴 시 주기적 전체 조회 없음
- 검증: 외부 편집·생성·삭제·이름 변경 시나리오, 감시 실패 대체 경로 테스트

### 검색 색인 캐시

- 문제: 검색·바꾸기 미리보기·보기 필터가 요청마다 프로젝트 전체를 순회하고, 검색은 확장자와 무관하게 모든 파일을 읽는다.
- 범위: 텍스트 확장자 우선 검색, 프로젝트별 색인 캐시와 감시 이벤트 기반 무효화
- 완료 조건: 반복 검색 시 전체 순회 없음, 결과·제한 안내 기존과 동일
- 검증: Rust 테스트(캐시 무효화·제한), 큰 프로젝트 반복 검색 시간 비교

## UI/UX 개선

2026-11-17 화면 점검 후 우선순위 조정. 기능 작업보다 먼저 진행한다.

### 문서 탭 개선

- 문제: 탭이 많아지면 넘친 탭을 찾기 어렵고, 순서를 바꿀 수 없으며, 같은 이름 문서(README.md 등)를 구분할 수 없다.
- 범위: VS Code 방식 탭. 넘칠 때 가로 스크롤과 활성 탭 자동 노출, 드래그로 순서 변경, 가운데 클릭으로 닫기, 같은 이름 문서는 폴더명을 덧붙여 구분, 전체 경로 툴팁. 미리보기(임시) 탭은 제외
- 완료 조건: 탭 순서가 세션에 저장·복원되고, 키보드(탭 포커스·Ctrl W·Ctrl Tab 등 기존 단축키)와 우클릭 메뉴가 유지된다
- 검증: 순서 변경·넘침 스크롤·같은 이름 구분 테스트, 데스크톱 앱에서 탭 20개 이상 조작

### 오버레이 스크롤바

- 문제: 브라우저 기본 스크롤바(7px)가 레이아웃 공간을 차지해 내용이 넘칠 때 패널 너비가 바뀐다.
- 범위: `guides/desktop-app.md` 기준 공통 `ScrollArea` 컴포넌트. 4~6px 막대만 표시, 스크롤 중·마우스 올림 시 나타났다 사라짐, 막대 드래그·트랙 클릭, 내용 크기 변화 반영. 사이드 패널(트리·검색 결과·프로젝트)부터 미리보기·설정·팔레트·메뉴까지 적용
- 완료 조건: 내용이 넘치든 아니든 영역 너비가 같고, 휠·키보드·드래그 스크롤이 기존과 같다. 스크롤 동기화와 미리보기 점진 렌더링이 유지된다
- 검증: ScrollArea 단위 테스트, 분리 전후 화면 스타일 비교, 라이트·다크 확인

### 문서 도구막대 정리

- 문제: 아이콘 9개가 설명 없이 나열되고, 바꾸기 버튼이 코드 아이콘을 쓴다.
- 범위: 찾기·바꾸기 / 실행 취소·다시 실행 / 개요·스크롤 동기화 / 저장 묶음과 구분선, 의미에 맞는 아이콘, 툴팁에 단축키 일관 표시, 좁은 폭에서 덜 쓰는 버튼은 더 보기 메뉴로
- 완료 조건: 모든 버튼의 아이콘·툴팁·접근성 이름이 기능과 맞고, 760px 이하에서도 한 줄에 들어간다
- 검증: 도구막대 테스트, 넓은·좁은 창 화면 확인

### 글자 수·저장 상태 표시

- 범위: 상태 표시줄에 글자·단어 수(선택 영역이 있으면 선택 기준), 현재 문서 저장 상태(저장됨·저장 안 됨·외부 변경)
- 완료 조건: 입력 중에도 앱 전체가 다시 렌더링되지 않고(상태 구독 선택자 전환 유지), 큰 문서에서 계산이 입력을 막지 않는다
- 검증: 계산·선택 영역 테스트, 렌더 횟수 테스트 유지

### 코드 블록 구문 강조

- 범위: 미리보기 코드 블록 언어별 구문 강조, 앱 테마(라이트·다크)와 어울리는 색, 지원 언어는 지연 로딩
- 완료 조건: 블록 단위 렌더링·점진 렌더링 성능이 유지되고, 알 수 없는 언어는 일반 텍스트로 표시된다
- 검증: 강조 결과·미지원 언어 테스트, 큰 문서 렌더 시간 비교

### 편집기 글꼴·줄 바꿈 설정

- 범위: 설정에 편집기 글꼴 종류(기본·설치된 고정폭 글꼴 입력)와 자동 줄 바꿈 켜기/끄기
- 완료 조건: 변경이 즉시 적용·저장되고 실행 취소 이력·스크롤 동기화가 유지된다
- 검증: 설정 파싱·저장 테스트, 편집기 반영 확인

### 안전한 HTML 허용

- 범위: 미리보기에서 `<details>`·`<summary>`·`<br>`·`<kbd>`·`<sub>`·`<sup>` 등 허용 목록 태그만 표시, 스크립트·스타일·이벤트 속성·외부 리소스는 계속 차단
- 완료 조건: 허용 목록 밖 HTML은 지금처럼 숨겨지고 보안 경계(TECH_STACK)가 갱신된다
- 검증: 허용·차단 태그와 속성 테스트
